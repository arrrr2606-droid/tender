# Мониторинг торгов на спецтехнику → Telegram

Каждые 30 минут система проверяет площадки и присылает в Telegram новые торги по вашим словам
(автогрейдер, экскаватор, погрузчик и т.д.) с учётом регионов.

| Площадка | Что там | Регион |
|---|---|---|
| ЕИС zakupki.gov.ru | госзакупки 44-ФЗ и 223-ФЗ (все федеральные ЭТП: Сбер-АСТ, РТС, Росэлторг…) | по ИКЗ / названию заказчика |
| torgi.gov.ru | продажа гос. и муниципального имущества | от площадки |
| Федресурс (ЕФРСБ) | торги по банкротству | по ИНН должника |
| B2B-Center | коммерческие закупки | от площадки |
| Фабрикант | коммерческие и 223-ФЗ | по названию заказчика |

Один и тот же лот приходит один раз. Если закупка из ЕИС продублирована на Фабриканте, второй раз она не придёт.

## Запуск на сервере (≈15 минут)

**1. Создайте бота.** В Telegram откройте @BotFather → `/newbot` → придумайте имя → получите токен
вида `123456:ABC...`.

**2. Арендуйте VPS в России.** Подойдёт любой с Ubuntu: Timeweb Cloud, Selectel, REG.RU. Хватит минимального тарифа: 1 vCPU и 1 ГБ RAM.
Сервер нужен российский: ЕИС, torgi.gov.ru и Федресурс закрыты для зарубежных IP.

**3. Установите Docker и загрузите проект** (в терминале сервера):
```bash
curl -fsSL https://get.docker.com | sh
```
Скопируйте папку `tender-monitor` на сервер, например через `scp -r tender-monitor root@IP_СЕРВЕРА:/opt/`.

**4. Впишите токен:**
```bash
cd /opt/tender-monitor && cp .env.example .env && nano .env
```
Заполните `TELEGRAM_TOKEN`. `TELEGRAM_CHAT_ID` пока оставьте пустым.

**5. Запустите:**
```bash
docker compose up -d --build
```
Напишите своему боту `/start`. Он ответит вашим chat id. Впишите его в `.env` как `TELEGRAM_CHAT_ID`
и перезапустите контейнер: `docker compose up -d`.
Чтобы лоты приходили в группу, добавьте бота в группу и напишите `/start` там.

При первом проходе бот сообщит, сколько актуальных лотов уже есть на каждой площадке, и отметит их
как известные. Дальше будут приходить только новые лоты.

## Управление из Telegram

| Команда | Что делает |
|---|---|
| `/list` | текущие слова, минус-слова, регионы |
| `/add бульдозер, каток` | добавить ключевые слова |
| `/remove каток` | убрать |
| `/exclude аренда` | минус-слово: лоты с ним в названии не придут |
| `/include аренда` | убрать минус-слово |
| `/addregion Татарстан, Самарская область` | искать только в этих регионах |
| `/removeregion Татарстан` | убрать регион |
| `/allregions` | вся Россия |
| `/kwregions погрузчик: ПФО` | свои регионы для одного слова (здесь — весь Приволжский округ) |
| `/kwregions погрузчик: общие` | вернуть слову общие регионы |
| `/status` | работают ли площадки, сколько отправлено |
| `/check` | проверить прямо сейчас |
| `/pause`, `/resume` | приостановить / возобновить |

Как можно указывать регионы: «Татарстан», «Московская область», «МО», «Москва», «СПб», «ХМАО», «Кузбасс»,
код «16», федеральный округ: ЦФО, СЗФО, ЮФО, СКФО, ПФО, УФО, СФО, ДФО.

**Если регион не удалось определить** (например, заказчик «Войсковая часть 12345»), лот всё равно
придёт с пометкой «регион не определён». Чтобы такие лоты не приходили, в `config.yaml` поставьте `strict_regions: true`.

## Прочие настройки — `config.yaml`

- `interval_minutes` — частота проверки (по умолчанию 30);
- `min_price` / `max_price` — фильтр по цене;
- `max_age_days` — не присылать лоты старше N дней (в ЕИС встречаются «зависшие» закупки многолетней давности);
- `sources` — включить или выключить площадки.

После правки выполните `docker compose up -d`. Ключевые слова, минус-слова и регионы из `config.yaml` берутся
только при первом запуске. Дальше они хранятся в `data/state.json` и меняются командами бота.

## Обслуживание

```bash
docker compose logs -f --tail 100     # логи
docker compose restart                # перезапуск
docker compose up -d --build          # обновление после изменения кода
```

Если площадка не отвечает три прохода подряд, бот пришлёт предупреждение. Обычно причина в том,
что площадка поменяла сайт: тогда нужно обновить соответствующий файл в `monitor/sources/`.

## Локальная проверка (без Telegram)

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt pytest
